# Project decisions

| Decision | Reason |
|---|---|
| Shared GitHub repo for source and docs | All four coding agents can use the same contracts and review changes. |
| Databricks SQL and Delta power live search | One searchable clip table connects ingestion to the demo. |
| Dataset annotations provide the first demo path | Frontend and backend can integrate while SurgVLP features are extracted. |
| Frozen SurgVLP with a small classifier first | Cached features let the team train and iterate without repeatedly running the backbone. |
| 2026-11-14: Team Databricks target is Aadhitya's workspace, catalog `workspace`, schema `default`, so the clip table is `workspace.default.surgf_clips` | One shared warehouse that every teammate's `.env` already points at. Avoids duplicate tables. |
| 2026-11-14: Train the tool-presence classifier in Databricks and track runs in MLflow. SurgVLP feature extraction stays off Databricks. Features go to the `workspace.default.surgf` Volume | The classifier on cached features is CPU-sized. MLflow gives reproducible runs and uses the sponsor platform. Extraction needs a GPU, which the workspace lacks. |
| 2026-11-14: Shlok selected Databricks GPU for SurgVLP extraction, superseding the earlier off-Databricks extraction decision | Keep full extraction and feature handoff in the team workspace. Local CPU checks validate the code first; cluster availability, credentials, CUDA execution, and Volume upload remain pending. |
| 2026-11-14: Shlok approved Databricks serverless CPU for the first demo cases and CPU classifier training | Classic GPU provisioning is blocked and serverless GPU did not execute. A real CPU smoke and full VID01 extraction succeeded. Keep all full extraction on Databricks; revisit GPU for larger workloads. |
| 2026-11-14: Use the dataset label `clipper` everywhere, including the fixture, SQL checks, contracts, backend tests, and search queries. Drop `clip applier` | The data, backend search, and frontend suggestions already use `clipper`. One name avoids empty searches. |
| 2026-11-14 (Aadhitya): Train one multi-label neural network (MLP on frozen SurgVLP features, ±5 s context option, per-label thresholds) on 6 instruments + 9 verbs + 14 targets (`null_verb` and `null_target` dropped), with the same frozen `expanded-v1` split. The logistic tool-only baseline stays as the reference. Full 100-class triplets are deferred | Verb/target labels already exist per frame, so no re-extraction is needed. One network shares features across labels and showed higher validation tool F1 than the logistic baseline in a local check. Most triplets are too rare to train. Search labels for verbs/targets need backend/frontend agreement before import. |
| 2026-11-14 (Aadhitya): **Search keeps all labels**: 6 tools, 9 verbs, 14 targets, for both `annotation` and `prediction` clips. Nothing is hidden; reliability is explained instead. The UI shows a source badge ("Labeled" for `annotation`, "AI-predicted" for `prediction`), groups suggestions as Tools / Actions / Anatomy with readable names (e.g. `cystic_duct` → "cystic duct", verb `clip` → "clipping" so it isn't confused with tool `clipper`), and explains that AI predictions for rare labels are unreliable. Per-label test F1 is recorded in ml/PROGRESS.md (MLP final run `3ce73d86…`). Label strings stay the plain dataset names, which are unique across groups, so the `/search` contract is unchanged. This supersedes the earlier "verb/target search needs agreement" note | Hiding labels would remove accurate human-labelled clips and make results look better than they are. Explaining reliability is more honest and keeps every query answerable. |
| 2026-11-14 (Mihir): Spatial boxes come from a supervised Faster R-CNN trained on Endoscapes (cystic duct, gallbladder), replacing the Grounding DINO zero-shot prototype | Grounding DINO produced visibly wrong labels; Endoscapes has reviewed anatomy boxes with a surgery-disjoint validation split, so quality can be measured. No instrument subtypes or liver: no box supervision for them. |
| 2026-11-15 (Mihir): Deploy the v3 native-resolution anatomy model on VID01 (validation AP 0.384) over v2 (0.352) | Best model on the labelled validation set; a weak 32-frame VID01 proxy favored v2 and v3 misses the duct at 11:38, accepted for the hackathon. VID01 accuracy is unmeasured; v2 can be restored from its checkpoint. |
| 2026-11-15 (Mihir): Spatial jobs may run on Databricks serverless CPU, split into parallel chunks; local runs remain valid | Keeps compute and MLflow tracking on the sponsor platform; a single 4-CPU job is slower than a recent Mac, so parallel chunks are used; outputs verified identical within rounding. |
| 2026-11-15 (Mihir): Add instrument boxes from a v4 detector trained with Endoscapes' generic `tool` class; keep v3 for anatomy; name instruments only when CholecT50 lists exactly one instrument and one tool box is detected | Endoscapes has no instrument types, so names must come from the per-second labels; the stricter rule avoids the swapped names seen with overlap-based carrying, at the cost of naming about a quarter of detections. v4's cystic duct was worse than v3, so anatomy stays v3. |
