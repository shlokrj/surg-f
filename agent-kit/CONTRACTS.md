# Shared interfaces

Initial search API: `GET /search?q=clipper`. Return an object with a `results` array, including an empty array for no match.

```json
{"results":[{"case_id":"case_01","start_sec":30,"end_sec":35,"label":"clipper","source":"fixture"}]}
```

Use the same keys in Delta, API responses, and frontend fixtures. Resolve case IDs to video assets through a shared case manifest. Verify the annotation timebase against actual playback. Keep fixture rows out of judging queries. Omit missing labels from the index; missing annotations do not establish a negative example.

For ML, keep one feature bundle per case, with a matrix of shape [frames, features] and a manifest in matching row order. Record the checkpoint and preprocessing. Join each row to its annotation by case ID and frame ID. Upload each bundle to `/Volumes/workspace/default/surgf/features/<case_id>/`, as `features.npy` plus `manifest.csv` with columns `case_id,frame_id`. Use the CholecT50 `video_id` (for example `VID01`) as `case_id` and `frame_number` (1 fps, seconds) as `frame_id`. Log each training run in MLflow with the SurgVLP checkpoint, preprocessing, train and test case IDs, threshold, and per-tool metrics. Export predictions with the same clip fields and source set to prediction.

## Stage 3 spatial artifact v1 (experimental branch)

The live player (on `main`, first built on `feat/spatial-overlays`) reads a static `/overlays/{case_id}.json` artifact; no backend route or search schema changes. Root fields: `schema_version: 1`, `case_id`, `video_asset_id`, `source` (`prediction`, `annotation`, `fixture`), positive integer `image_width`/`image_height`, `max_age_sec` (0 < age ≤ 0.25), nonempty `provenance`, and `frames`. Frames have unique nonnegative integer `frame_id`, strictly increasing nonnegative `timestamp_sec` in player seconds, and `detections`. Each detection has a frame-local unique `instance_id`, `category` (`instrument` or `anatomy`), `label`, finite `score` in [0,1], and normalized source-image `bbox_xyxy: [x1,y1,x2,y2]` with positive area. Instance IDs do not imply tracking.

Current labels: six existing instrument labels; experimental anatomy subset gallbladder, liver, cystic duct. The deployed VID01 artifact (v3 model, 2026-11-15) uses only gallbladder and cystic duct. For artifacts exported from a decoded video, `frame_id` is the decoded frame index and `timestamp_sec` = stream start + `frame_id` / fps; dataset (CholecT50) offsets apply only to dataset frame IDs. No verbs or inferred relationships. Producer validation lives in `ml/localization/artifact.py`; consumer validation in `frontend/src/overlays.js`. Limits: 20,000 frames, 100 detections per frame, and frontend text payload of 4 million characters (raised from 10,000 and 2 million on 2026-11-15 so the 47-minute VID02 fits at the same 0.24 s sampling as VID01). A missing artifact (HTTP 404, or an HTML fallback page) is reported as "no bounding boxes for this video yet" without a retry. Case/asset/dimension mismatch rejects rendering. Optional paired `display_width` and `display_height` positive integers bind an artifact to the browser's displayed video dimensions when the decoded source has non-square pixels; without them, source dimensions must match the browser dimensions. Normalized boxes still span the entire displayed image. VID01's MP4 decodes at 854×480 with pixel aspect ratio 253:255, while Chrome 157 exposes 854×484; its artifact declares both dimensions explicitly. Asset ID is a deployment binding, not a video checksum verification. Sparse frames expire; no interpolation across gaps.

See [runner instructions](../ml/localization/README.md) and [localization plan](../ml/LOCALIZATION_PLAN.md). This is an experimental implementation contract, not a production spatial API agreement.
